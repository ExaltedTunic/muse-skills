# Contributing

This is a living collection shared among friends. Skills can come back the other way too; this is what a skill needs before it lands here.

## House rules

1. **Tested in real use.** A skill earns its place by working in someone's daily setup, not by sounding plausible. Say what it was tested on.
2. **Generic by design.** The method travels, personal data does not. Names, addresses, emails, account details, balances, and stories about a specific household stay out, unless a reader explicitly needs a labelled example with a placeholder.
3. **Scrub the whole folder.** Private values hide in scripts, config defaults, comments, and example files as easily as in the main document. Run a text search over the finished folder for every identifier class before proposing it, and report zero hits. The scrub-before-sharing skill in this repo is the workflow.
4. **Keep the shape.** One folder per skill under `skills/`, containing at minimum a `SKILL.md` and a `skill.yaml` with name, title, description, and category. Scripts and example configs live inside the skill's folder.
5. **Third-party work gets a link, not a mirror.** Only redistribute someone else's work when its license clearly allows it, with attribution and the license text included.

## Proposing a skill

Open an issue or a pull request with the skill folder, a one-line entry for the README catalogue, and a changelog note: what it does, what it needs, and what it was tested on.
